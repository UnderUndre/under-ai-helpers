### Component 1: Two-Phase Review Flow (new constitution Principle VIII)

Establishes a `discovery PR → delivery PR` pattern for every full-pipeline SpecKit feature:

- **Planning branch** named `specs/<slug>` — contains ONLY files under `specs/<slug>/**`. Opened as PR, reviewed by AI agents via /speckit.review (≥2 external reviewer PASS per Principle VI), merged to main FIRST.
- **Implementation branch** named `<slug>` — contains actual code changes referencing the now-merged spec. Opened as PR, reviewed via /code_review or agent, merged AFTER planning PR.
- **Drift policy**: if during impl the spec turns out wrong, patch it via normal PR to main (treat as bug fix). Do NOT block impl.
- **Hotfix carve-out**: explicit exemption in constitution. Production hotfixes (defined: change <50 LOC, fixes prod incident with ticket reference) skip the two-phase flow.
- **CI policy**:
  - `specs/*` PRs run ONLY: markdown lint, link check, /speckit.analyze regen + check verdict.
  - `<slug>` PRs run: full test suite, build, lint, type check, /speckit.analyze re-validation.
- **PR templates**:
  - `.github/PULL_REQUEST_TEMPLATE/spec.md` — sections: feature goal, user scenarios, FRs, NFRs, edge cases, questions for AI reviewers.
  - `.github/PULL_REQUEST_TEMPLATE/impl.md` — sections: spec link, files touched, test plan checklist, breaking changes, rollback plan.
- **Auto-cleanup**: GitHub Action or repo setting to delete `specs/<slug>` branch after merge.
- **`/speckit.start` update**: must create `specs/<slug>` branch first (planning phase), then on `/speckit.implement` invocation switch worktree to `<slug>` branch.

### Component 2: `clai-helpers hermes` wrapper command (packages/cli/)

A new CLI subcommand that wraps the `hermes -z` invocation documented in .claude/commands/hermes-invocation.md, eliminating the magic snippet copy-paste:

- `clai-helpers hermes <prompt>` — basic usage
- `clai-helpers hermes --from-file <path>` — read prompt from file
- `cat prompt.txt | clai-helpers hermes` — read prompt from stdin
- `--background` flag → spawn detached, return PID + log path (e.g. `.hermes-output-<timestamp>.log`)
- `--model <name>` → override model (default: `glm/glm-5.1`, env override: `HERMES_DEFAULT_MODEL`)
- `--provider <name>` → override provider (default: `custom`)
- `--toolsets <csv>` → pass through to hermes
- `--verbose` → pass through
- Detects hermes binary on PATH; if missing, prints clear install hint and exits 127.
- Returns hermes's exit code.
