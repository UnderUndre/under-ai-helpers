## Summary

The spec is clean as a *configuration* document — clear per-field precedence tree, good acceptance scenarios, sensible clarifications. `opencode` already filed 7 HIGH/6 MEDIUM at the document level. But probing against the **actual code** surfaces a problem that outranks all of them and that both `analyze.md` (PASS, "0 findings") and `opencode` missed: **the subsystems 009 makes "configurable" are not wired to the running server.** `createBackend()` (the feature-008 Honcho seam) has **zero call sites**; `mcp-server.ts` still routes `memory_recall`/`memory_write` through the old 005-era direct-SQLite path; the embedding pipeline 009 configures still uses a **hash-stub tokenizer** that produces semantically meaningless vectors. So a fully-implemented 009 (all of T001–T015 green) would let a user set `--honcho-endpoint` and observe **no behavioral change** — SC-001 cannot pass as written. Compounding this, 009 silently contradicts sibling feature **008** (whose FR-005 says *delete* the ONNX embedding pipeline that 009's US2 *configures*) and never references it. Headline weakness: **009 is plumbing for a backend that isn't connected.** Verdict: CRITICAL.

## Alternative approaches considered

1. **Single resolver, not scattered reads.** Thread one resolved `UnderboardConfig` from `loadConfig` → `startServer` → `createBackend` + `initializeEmbedding`, and delete the ad-hoc `opts.port ?? process.env.PORT ?? config.port` ladder in `index.ts:24` (which double-resolves PORT now that c12 already merges env). One resolution point makes FR-004 precedence testable and removes the existing anti-pattern. Worth adopting regardless of the findings.
2. **Zod validation of `config.json`** (raised by `opencode`): a runtime schema would catch `"port": "not-a-number"` and ties directly to F12 coercion. One dependency; real error-message gain for a user-facing config surface. Author's call.
3. **OS keychain for secrets** (raised by `opencode`): heavier (native module), eliminates F5's at-rest exposure. Likely overkill for a single-user local tool; flagging, not recommending.
4. **Sequence 009 behind 008's wiring + tokenizer fix.** If F1/F2/F3 are accepted, the cleanest path is: finish wiring `createBackend` and replace the stub tokenizer (008 territory) *first*, then 009 becomes pure, testable config plumbing. As-is, 009 is testing config against a disconnected substrate.
