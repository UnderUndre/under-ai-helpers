# SpecKit Review: 005-agents-board-and-memory

**Reviewer**: claude
**Reviewed at**: 2026-05-28T14:10:22Z
**Commit**: 95af8e98dc9855c98689a4483add3311f0509ab3
**Artifacts reviewed**: spec.md, plan.md, tasks.md, data-model.md, research.md, quickstart.md, contracts/memory-tools.md, contracts/task-tools.md, constitution.md, reviews/analyze.md, reviews/antigravity.md

## Summary

The design is solid as a happy-path system: the dedup + provenance model, hybrid retrieval, and the spec's explicit separation between project-scoped and cross-project recall are good shape. But the security model collapses under one observation — **"localhost-only" is not an access boundary in a multi-tenant browser**. The plan describes a long-lived HTTP/SSE service with zero authentication, zero Origin/Host validation, and no explicit bind-to-loopback in tasks; combined with a `memory_delete` that has no authorization and a `memory_recall_cross_project` that returns content across every project the user has ever touched, any webpage the user visits in the same browser session can read and wipe their entire AI memory. Antigravity flagged the stored-XSS variant; the deeper issue is the trust model itself. Outside security, there is one HIGH data-integrity finding (concurrent task overwrite has no CAS primitive), and several MEDIUM gaps around offline-first claims, transport pinning, and naming consistency.

## Findings

| ID | Severity | Area | Finding | Recommendation |
|---|---|---|---|---|
| F1 | CRITICAL | Security / threat model | **Localhost-only trust model is unenforced and porous.** Plan T016 (`src/server/http-server.ts`) and quickstart.md L33–L35 describe HTTP+SSE on `localhost:4280`, but (a) Node's `server.listen(4280)` without an explicit host defaults to `0.0.0.0` / `::`, exposing the service to the LAN; FR-028 ("MUST listen on loopback by default") has no task that enforces it. (b) No Origin/Host header validation on `/api/tasks`, `/events`, `/health`, or `/mcp/sse` is specified anywhere — a malicious webpage in the user's browser can issue CORS-safe GETs and `fetch` with `mode: 'no-cors'` POSTs to localhost, and **DNS rebinding** turns any attacker domain into "localhost" for the victim's browser. (c) `memory_delete` (contracts/memory-tools.md L168) explicitly states "Any agent can delete any entry" — combined with (a)/(b), any webpage can wipe the user's entire AI memory by enumerating UUIDs from the SSE stream. (d) `memory_recall_cross_project` returns content from every project. A drive-by request can exfiltrate every memory the user has ever stored. | Defense in depth, three layers: **(1)** Explicit bind `127.0.0.1` in T016 (or `--bind 0.0.0.0` opt-in). **(2)** Origin/Host allowlist middleware: reject requests whose `Origin` header isn't `http://localhost:<port>` or `http://127.0.0.1:<port>`, and whose `Host` header isn't `localhost`/`127.0.0.1`/IP. This kills DNS rebinding. **(3)** A 32-byte bearer token generated on first start, written to `~/.underboard/token` with mode 0600, required on every HTTP and MCP request — one config line in the agent's MCP setup. Add a security FR and tasks: T016 must implement (1)+(2), a new T016b implements (3). Document in quickstart.md. |
| F2 | CRITICAL | Authorization | **`memory_delete` has no scope check.** Contracts/memory-tools.md L168: "Any agent can delete any entry. Operator can also delete via dashboard." A buggy or compromised agent in project A can wipe memory for project B by iterating UUIDs (visible via SSE `memory_added` payloads or `memory_recall_cross_project`). Combined with F1, this is a remote one-shot wipe via any webpage. The spec edge case ("provide a delete tool so leaks can be expunged manually") never said "any agent, any project". | Scope `memory_delete` to the calling agent's current project by default. Add a separate, explicit `memory_delete_cross_project` tool that requires the caller to supply the source `project_id` (mirroring the `memory_recall` vs `memory_recall_cross_project` pattern already in the spec). Add a rate-limit (e.g., max 100 deletes per minute per session) to defang scripted enumeration. Update FR-005 to specify scope. |
| F3 | HIGH | Data integrity | **Last-write-wins on tasks has no CAS / version field — silent overwrites.** Assumption 8 chooses last-write-wins; the `task_update` contract (contracts/task-tools.md L52–L75) accepts no `expected_updated_at` / `if_match` / version token. Two agents that fetch a task, decide on different transitions, and write simultaneously: one wins, the other doesn't even learn that its change was overwritten. The spec edge case claims "each write returns the resulting state so callers can detect overwrites if they care", but without knowing the previous state the caller cannot detect anything — the return shape just says "current is X". | Add an `if_match: { updated_at: string }` optional param to `task_update`. When supplied and the stored `updated_at` doesn't equal it, return `409 CONFLICT` with the current task body so the caller can re-resolve. Keep last-write-wins as the default when `if_match` is omitted (back-compat). This is a 30-LOC change in T012 and gives multi-agent flows opt-in safety. |
| F4 | HIGH | Failure mode | **Crash between `memory_entries` insert and `memory_vectors` insert leaves stuck entries that the backfill worker won't fix.** T009 inserts into `memory_entries` (with `embedding_status='ready'` once embedded) and separately into `memory_vectors` (data-model.md L156–L157, "Application-level. On embedding computation, INSERT or UPDATE into `memory_vectors`."). If the process crashes between the entry update setting status to `ready` and the `memory_vectors` INSERT, the row has `embedding_status='ready'` but no vector. The backfill worker T033 only scans `WHERE embedding_status='pending'`, so this entry is permanently missing from semantic recall and never gets a vector. There is no transaction binding the two writes. | Either (a) wrap both writes in a single SQLite transaction (better-sqlite3 supports this via `db.transaction()`), or (b) flip the order: insert into `memory_vectors` first, then update `embedding_status='ready'` — so the only crash window leaves `status='pending'` with a vector already present, and the backfill worker can be augmented to upsert the vector if missing. Add a self-heal step in T033 to also scan for `status='ready'` with no matching `memory_vectors` row. |
| F5 | HIGH | Offline-first claim | **SC-012 ("offline-first") contradicts the first-run network requirement.** Spec SC-012 promises "with the machine disconnected from the internet after first install, all memory operations continue to work" and Assumption 12 says the model "runs comfortably on commodity laptop hardware". But quickstart.md L30–L31 and tasks.md T007 require an internet download of `~80MB` ONNX model on first run. If the user installs offline (e.g., from an enterprise mirror or air-gapped dev box), the service has no path to a usable state — memory writes accept content but the embedding stays `pending` forever; recall degrades to lexical-only with no recovery. Nowhere in spec/plan/tasks is "first install must occur online" stated. | Add an FR: "First install requires one-time network access to fetch the embedding model; subsequent operation is fully offline." Add a CLI command `underboard model fetch` (T024) that can be run separately for air-gapped install via sideloaded `.onnx` file in `~/.underboard/models/`. Soft-warn the assumption gap in quickstart.md. |
| F6 | HIGH | Semantic inconsistency | **`task_list_assigned` defaults to cross-project, breaking the symmetry the spec carefully built.** Spec FR-007 establishes that "Default memory retrieval MUST be scoped to the agent's currently-detected project." Cross-project requires a SEPARATE tool. But contracts/task-tools.md L129 makes `task_list_assigned` cross-project by default ("Cross-project by default — agent sees all their tasks across projects"). Inconsistent mental model: memory scoping is explicit, task scoping is implicit. Worst-case: operator creates "do laundry" assigned to "claude" in personal-project; Claude in client-project gets that task back from `task_list_assigned`. Surprising. | Mirror the memory pattern: `task_list_assigned` defaults to current project; add `task_list_assigned_cross_project` as an explicit tool. Or: add a required `scope: 'current' \| 'all'` param with no default, so the agent has to declare intent. Update FR-011 to specify. |
| F7 | HIGH | Performance / availability | **No SSE backpressure for slow consumers.** T017 (`src/events/event-bus.ts`) is "in-process EventEmitter-based pub/sub. On event: (1) persist to events table, (2) push to all connected SSE clients." If a dashboard tab is OS-suspended (laptop closed, tab backgrounded for hours) and agents emit 100 events/sec, the per-client send buffer grows unboundedly — Node's `res.write()` queues bytes when the kernel socket buffer fills. Memory footprint blows past the 512MB SC-007 budget and risks OOM. No spec for buffer cap, drop policy, or disconnect on lag. | Per-client backpressure: track each SSE client's pending-write byte count; when above a threshold (e.g., 1MB), drop the slowest events or close the connection with a "you missed too much, full-snapshot reconnect required" message — which the client already handles via the "gap > 1000 events" path in research.md R4. Add to T017 description. |
| F8 | MEDIUM | Naming consistency | **`underboard` (npm bin) vs `memory-board` (directory) vs `board-mcp` (brainstorm name) — three names for one thing.** T001 declares `package.json` `name: underboard`, directory `packages/memory-board/`, brainstorm and spec referred to `board-mcp`. quickstart.md uses `underboard` as the CLI. This makes greps, error messages, and search confusing for ever after. | Pick one. Recommend `underboard` for both directory and npm name (`packages/underboard/`, `name: underboard`, bin `underboard`). Update spec assumption text, plan, tasks, quickstart. Or document the rename explicitly in tasks.md. |
| F9 | MEDIUM | Transport pinning | **MCP transport version not specified.** Assumption 15 ("targeted version is current at time of release") is open-ended. MCP shipped a breaking transport change with "Streamable HTTP" (2025-03-26 spec) — single endpoint replacing the dual `/sse` + `/messages` pattern of pre-2025 versions. quickstart.md L33–L34 implies a single `/mcp/sse` endpoint, which doesn't match either common topology exactly. If the implementer picks the wrong version, agents fail to connect with confusing errors. | Pin to a specific MCP transport revision in plan.md §Technical Context (e.g., "MCP transport: HTTP+SSE per 2024-11-05 spec, single `/mcp/sse` endpoint for both directions" OR "Streamable HTTP per 2025-03-26 spec, single endpoint with method switching"). Update T015/T016. Add compatibility matrix to quickstart. |
| F10 | MEDIUM | Edge case | **Workflow conventions for `blocked` and `review` statuses are undefined.** FR-013 / contracts/task-tools.md L232 lock the five statuses, but no document says when an agent should choose `blocked` vs `review` vs `backlog`. Without convention, Claude will use `blocked` for "I'm waiting for human input", Gemini will use it for "I'm rate-limited", Codex won't use it at all. The board becomes inconsistent immediately. | Add a short "Status semantics" subsection in spec.md or contracts/task-tools.md with one-line definitions of when to use each status. E.g., `blocked` = "external dependency not satisfied"; `review` = "human approval needed before next action". |
| F11 | MEDIUM | Contract clarity | **`memory_list_recent` truncates content to 500 chars but contract doesn't return a truncation flag.** contracts/memory-tools.md L138 says "Truncated to 500 chars with '...' suffix if longer". Caller cannot reliably distinguish "content actually ended in '...'" from "content was truncated". Caller also has no path to fetch full content (there is no `memory_get_by_id` tool). | Add `truncated: boolean` and `full_length: number` to each entry in `memory_list_recent` results. Or add a `memory_get` tool that returns the full entry by ID. The latter is more useful — recall is hit-and-miss for "I know the ID, give me the full text". |
| F12 | MEDIUM | Implementation gap | **Agent CWD injection mechanism unspecified.** T015 says "Add middleware to inject `ToolContext` (project_id, agent_name, cwd) from request metadata." But MCP protocol doesn't natively carry CWD or agent name — the client must self-report. If Claude Code passes CWD on connection initialization but Cursor doesn't, project detection silently falls back to `global` for Cursor — every memory and task ends up in the uncategorized bucket. | Specify the wire mechanism: e.g., agents pass `client_info: { name, cwd }` in MCP `initialize` request (per MCP spec capability negotiation), or a custom HTTP header on `/mcp/sse` connect. Document the required client behavior in quickstart.md so non-Claude clients can be configured correctly. Add a health-endpoint field `clients: [{ agent, cwd, project_id }]` for debugging when project detection misfires. |
| F13 | MEDIUM | Recall quality | **`all-MiniLM-L6-v2` is English-trained; multilingual queries degrade silently.** R2 picks MiniLM for size/speed but it's a monolingual English encoder. Russian, Cyrillic, mixed-language content (a real concern for this codebase per the persona/CLAUDE.md tone) will embed poorly — recall returns mostly noise. No FR or assumption acknowledges this. | Either pin English-only as an Assumption (and document the limitation), or swap to a multilingual model (`paraphrase-multilingual-MiniLM-L12-v2` is ~120MB, paraphrase quality across 50+ languages including ru/en) and re-check the 512MB budget in SC-007. Add to research.md R2 the multilingual evaluation. |
| F14 | MEDIUM | Storage growth | **Provenance list has no cap; hot-content explodes.** Dedup merges provenance entries. If 1000 agent sessions over a year write the same canonical fact ("Auth uses JWT with 1h TTL"), the entry's provenance JSON grows to 1000 entries. Every recall returns that bloated list — token cost on every call, response payload bloat, no UI for showing "first N + last N + count". | Cap provenance at N entries (e.g., 20). When exceeded, keep first 5 (original assertions) + last 10 (recent re-assertions) + a `truncated_count: N-15` field. Or move provenance to a separate `memory_provenance` table queryable via a `memory_get_provenance` tool. Update memory_entries schema in data-model.md. |
| F15 | LOW | Accessibility | Dashboard plan/tasks make no mention of a11y (ARIA, keyboard navigation, color-contrast for the kanban columns). For a tool that solo developers will keep open all day, basic keyboard navigation (arrow keys to move between cards, enter to open) is a notable UX win and a11y baseline. | Add an a11y checklist to T018 (semantic HTML, ARIA roles for kanban columns, keyboard nav for cards, focus management for modals) and a sentence in quickstart Dashboard section. |

When event gap > 1000, server "sends a full state snapshot instead" — but the wire format is not specified. Client cannot implement a fallback path without knowing the shape. | Specify the snapshot event shape: e.g., a single `event: snapshot\ndata: { tasks: [...], memory_recent: [...], last_event_id: N }\n\n` after which live events resume. Add to research.md R4 and T019 (SSE client). |

## Alternative approaches considered

- **Project identity** (already raised by antigravity F2): a complementary alternative — instead of *either* path hash or git-remote hash, store BOTH in the `projects` table (path hash as primary key for stability against remote URL rewriting, git remote URL as a secondary `stable_key` for cross-machine reconciliation). On import, match by `stable_key` first, fall back to path hash. Best of both, costs one column.

- **Auth model**: brought up in F1. Two competing options worth weighing — bearer-token-in-config (simplest, works for all MCP clients) vs Unix-socket-only (no HTTP exposure at all, but breaks the dashboard which needs a browser). The bearer token + 127.0.0.1 bind + Origin allowlist combination is the lowest-friction defense-in-depth and the recommended choice.

- **Async write durability**: an alternative to F4's transaction approach — use SQLite's `journal_mode=WAL` (already planned) plus a single "write all memory artifacts atomically" stored procedure / pragma boundary. Less code than per-call transactions, but harder to reason about. Transactions are the simpler choice.

- **Memory mutation model**: Assumption 6 forces immutability and forces "agents write a new contradicting fact" for updates. An alternative not weighed: a `supersedes: id?` field on memory_entries so newer entries explicitly invalidate older ones, surfaced in recall with `superseded: false` filter by default. This would address the conflict-fact problem without breaking immutability (old entries kept for audit, just hidden from default recall).
